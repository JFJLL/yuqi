# Ticket 07：AI 巡检、人工复核与整改

## Outcome

管理员使用经理版 AI 巡检列表和详情处理疑似风险；只有人工复核通过的结果才能推送员工整改，并完整保留证据与修订记录。

## Blockers

Ticket 01、Ticket 06。

## Scope

- 经理版巡检列表、筛选、状态、详情和证据展示。
- 人工复核通过/驳回/修订，推送整改，整改反馈、补充证据、修订和确认。
- 合并当前独立整改任务入口，形成一个可追踪状态链。
- 任务领取和状态转换需原子化、幂等并审计。

## Ownership

独占巡检与整改页面、状态机、API/schema 增量及测试。录音只读引用 Ticket 06 契约；申诉处理归 Ticket 08。

## Acceptance

1. AI 输出始终标为疑似风险，未经人工复核无法被员工看到或形成整改任务。
2. 状态转换拒绝越权、重复和过期操作，所有决定可追溯。
3. 员工反馈、证据和管理员修订在同一详情上下文可见。
4. 为培训任务提供稳定的问题/规则来源引用。

## Evidence

返回状态图、API 契约、并发/越权/人工门禁测试、列表与详情截图、提供给 Ticket 08/10/13 的引用契约。

## Verification

先运行完整状态机、人工门禁、并发、权限和 UI 定向测试，再运行 `rtk pnpm verify`；修改后执行 `$code-review`。
