# Ticket 02：微信手机号登录与原生小程序基础

## Outcome

测试环境可以从原生小程序完成微信手机号登录或首次资料关联；生产路径具备真实 code 交换边界，未配置凭据时安全失败。

## Blockers

无。

## Scope

- 将经理原生小程序结构按当前项目工程规范纳入，但不复制不安全认证实现。
- 建立小程序请求层、认证状态、登录页、首次资料关联页和基础导航壳。
- 新增 `wechat_accounts` 映射与服务端登录/绑定接口。
- 测试环境支持明确标记的 mock code；生产环境必须校验微信返回，不能固定验证码或自动建真实员工。
- 补充登录并发、重复绑定、手机号已占用、员工不存在、微信服务失败等分支。

## Ownership

独占新建的小程序目录、服务端微信认证服务/路由、`wechat_accounts` 迁移与对应测试。可以修改服务端认证公共模块，但禁止修改后台认证客户端、`AdminLayout.tsx`、`App.tsx` 或后台业务页面；如服务端公共契约变化，只通过独立类型/接口文件通知 Ticket 01。

## Acceptance

1. `loginCode + phoneCode` 服务端交换、员工手机号匹配、微信账号绑定和令牌返回契约完整。
2. 测试 mock 仅在测试配置下启用，UI 有明确测试标识。
3. 重复点击、同微信绑定不同员工、同员工绑定不同微信都有确定行为和审计信息。
4. 小程序登录态可恢复，退出后本地敏感状态清理。

## Evidence

返回迁移字段、接口请求/响应/错误码、测试结果、小程序登录与关联截图、生产配置缺失时的失败证据。

## Verification

先运行认证集成测试和 schema 检查，再运行 `rtk pnpm lint`、`rtk pnpm typecheck`、`rtk pnpm test`、`rtk pnpm build`；运行项目可用的 `rtk pnpm exec miniprogram-ci` 编译检查，修改后执行 `$code-review`。
