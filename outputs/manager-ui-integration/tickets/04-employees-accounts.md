# Ticket 04：员工、店长与微信关联状态

## Outcome

管理员可按经理版页面管理员工、店长、门店归属和微信绑定状态，并通过批量操作维护测试数据。

## Blockers

Ticket 03。

## Scope

- 员工列表、筛选、详情、新增、编辑、启停、角色/门店分配。
- 批量导入模板、逐行校验、部分失败报告和导出。
- 展示微信未绑定/已绑定/待审核等状态，提供安全解绑或重新关联流程。
- 复用当前员工认证能力，不削弱手机号唯一性和本人数据边界。

## Ownership

独占员工管理页面、员工管理 API/schema 增量和测试。微信 code 交换与 `wechat_accounts` schema 归 Ticket 02；组织结构归 Ticket 03。

## Acceptance

1. 员工与门店/角色关系完整，手机号冲突和跨租户关联被拒绝。
2. 批量导入有预检查和可下载错误明细。
3. 解绑需要权限、确认和审计，且不会产生可接管账号的窗口。
4. 经理版组织页中的员工操作均有对应入口与反馈。

## Evidence

返回字段和接口契约、批量样例、范围与解绑安全测试、员工页截图，并通知 Ticket 05/13 可用的员工 API。

## Verification

先运行员工、认证关联、权限和导入导出定向测试，再运行 `rtk pnpm verify`；修改后执行 `$code-review`。
